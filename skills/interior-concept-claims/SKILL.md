# 室内概念册 · 主张大纲

蒸馏自 deck-outline-first。挂在大纲架构师（OT-*/SO-*-CONCEPT + page_type）**之后**。
把设计判断落成：**符合项目叙事的标题 + 一行证据备注**，不把推理过程贴到页面。

## 何时用
- 准备生成/出页前要过叙事关
- 用户要「思考也写进 PPT」→ 用本 skill 的 claim+evidence，禁止旁白落页

## 项目叙事口径
先沿用用户与总监已确认的受众、标题视角及页型规则。用户旅程、空间体验、短标签等已确认形式不因本技能被改回判断句；仅在项目未定口径时，使用下面的主张句建议。证据可以是图像、场景、空间关系或经核对的数字，不要求每页有数字。

## 页型分流
**未定口径时建议用主张句**
- 场地矛盾 / 客群结论 / 定位
- CONCEPT_SOURCE · MAPPING · 概念演绎
- 空间叙事结论、策略、造价/系统建议（若有）
- 总部办公：问题→方案→效果序列中的叙事页

**可用短标签（不硬套 claim）**
- COVER · TOC · SPACE_DIVIDER / 扉页
- 平面 / 动线示意 · 材料板 · 色板 · 纯图 RENDER/MOODBOARD
- 附录与索引

## 规则
1. **一页一个表达任务**：标题遵循已确认视角；未定口径时，叙事页可用完整、可核对的主张句。
2. **Skim test**：只读标题应讲清 场地→概念→各空间回应→收束（总部则对齐五章链）。
3. **证据备注**：每页一行；无证据标「愿望」并降级或删。
4. **证据过多** → 拆页。
5. **出页忠实**：静默加页必须重新 skim。

## 室内证据举例（可核对）
- 现场：层高不足、柱网挡视线、物流与客流交叉
- 客群：到访节奏、停留、私密/展示冲突
- 甲方原话 / 任务书指标（有出处）
- 材料：做法节点、维护周期、与母题的关系
- 对标：可指认的项目与具体空间，不写「国际一流」

## 输出
```
模板: SO-…/OT-…
主张大纲:
1. [COVER] 短标 — evidence: …
2. [CONCEPT…] 项目已确认口径的标题。 — evidence: …
Skim: 通 / 卡在第k步：…
```

## 硬禁
- 不发明面积/造价/品牌对标数字
- 不把封面/材料板/平面改成 pitch 标题
- 不绕过业态模板选型
